### Fixed

- Fix, in builds with `ZORBA_FOR_ONE_THREAD_ONLY=OFF`, crashes and races when
  clones of one query run in parallel, or when queries compiled against one
  static context are compiled and run in parallel: user functions were
  optimized and their plans generated lazily, by their first call at run time
  or by the first query that called them, on objects that every query shares,
  and every query compiled against a static context loaded with `loadProlog()`
  rewrote the prolog's expressions. Compilation is now sealed: `compile()`
  optimizes and generates the plan of every user function the query can
  reach, and `StaticContext::loadProlog()` (and a query with `eval` or
  `fn:function-lookup`) does it for every function it declares. The optimizer
  no longer rewrites, annotates, inlines or optimizes an expression or a
  function of another compilation.

### Changed

- Compilation does more work and execution less: plans of user functions are
  generated by `compile()`, not by their first call. An error that generating
  a plan raises is still raised when a call to the function opens, and an
  error found in a function of a loaded prolog is still raised by the
  compilation of a query that calls it.
- The functions and variable initializers of a prolog loaded with
  `loadProlog()` copy the input nodes of their element and document
  constructors, since they no longer depend on which query uses them; these
  functions are no longer inlined into the queries that call them.
