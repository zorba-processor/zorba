### Fixed

- Fix, in builds with `ZORBA_FOR_ONE_THREAD_ONLY=OFF`, crashes and races when
  clones of one query run in parallel, or when queries compiled against one
  static context run in parallel: user functions were optimized and their
  plans generated lazily, by the first call at run time or by the first query
  that called them, on objects that every query shares. Compilation is now
  sealed: `compile()` optimizes and generates the plan of every user function
  the query can reach, and `StaticContext::loadProlog()` (and a query with
  `eval` or `fn:function-lookup`) does it for every function it declares.
  Compiling or running another query no longer changes them: the optimizer
  does not rewrite, inline or annotate a function of another compilation.

### Changed

- Compilation does more work and execution less: plans of user functions are
  generated by `compile()`, not by their first call. An error that generating
  a plan raises is still raised when a call to the function opens.
- The functions of a prolog loaded with `loadProlog()` copy the input nodes of
  their element and document constructors, since the functions no longer
  depend on which query calls them; they are no longer inlined into the
  queries that call them.
