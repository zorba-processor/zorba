### Breaking changes

- The library default security policy is now `SecurityPolicy::secure()`. A program that embeds Zorba and does not call `Zorba::setSecurityPolicy()` runs queries that cannot read or write files, use the network, import modules or schemas over the network, expand external entities, load native modules or read environment variables: `fn:doc` and `fn:unparsed-text` on files or URLs fail with the error the specification prescribes for an unavailable resource (for example `err:FODC0002`), importing the file, http-client, ftp-client or another native module fails with `zerr:ZXQP0067`, the environment functions return the empty sequence, and `ZORBA_URI_PATH` / `ZORBA_LIB_PATH` are ignored. Allow what the application needs with `SecurityPolicy::secure().allow(...)`, or call `zorba->setSecurityPolicy(SecurityPolicy::unrestricted())` to keep the behavior of earlier versions. The `zorba` command line still runs queries unrestricted unless `--secure` is given. See the new "Security Policy" documentation page.
