### Added

- `zorba-mcp` keeps a few small parsed documents across tool calls, for the documents that `dir:open` and `dir:documents` read repeatedly. This document cache is separate from the background scan's memory (`--scan-cache-mb`), which holds the listing and previews for `list_documents` and serves no query. `--cache-max-file-kb <KB>` (default 16) is the largest file kept and `--cache-max-files <N>` (default 10) how many documents stay, least recently used out first; `0` in either turns the cache off. A document enters on its second read; the first read does the work it does without a cache, and a larger file gets one `stat`. A document is served only while its file has the same canonical path, device, inode, size, modification time and change time. Records with an error, and records that take more than 128 times the size of their file in memory (as internal XML entities can make them), are not kept. Updating and sequential queries do not use the cache, and the security policy is unchanged. A query cannot store content in the cache. `hits`, `misses`, `admissions`, `evictions` and `bytes_retained` go to stderr in one line when the server exits, not to tool responses.
- Module `http://zorba.io/modules/directory-cache` (`dc:get`): the hook through which the directory module looks up parsed documents. The installed implementation returns nothing, so `zorba --directory` and embedders read every file as before; an embedding application can resolve the module to its own external function.

- The directory module no longer triggers a deprecation warning (`ZWST0008`) each time it compiles.
