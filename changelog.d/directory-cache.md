### Added

- `zorba-mcp --cache-mb <MiB>` (default CACHE_DEFAULT, 0: off): the documents that the directory module parses are kept across tool calls, up to that much estimated memory (file size times 20 for XML, 22 for JSON, 32 for CSV, as measured), least recently used first; entries used by the current call are not evicted, so a call that reads more than the budget keeps the documents it cached first. A document is served from the cache only while its file has the same canonical path, device, inode, size, modification time and change time; entries of modified or deleted files are dropped before each call. Only files under `--root` are cached, the security policy is unchanged, and updating or sequential queries do not use the cache. The cache builds each record itself, by running `dir:open` under the server's policy; a query cannot store content in it.
- Module `http://zorba.io/modules/directory-cache` (`dc:get`): the hook through which the directory module looks up parsed documents. The installed implementation returns nothing; an embedding application can resolve the module to its own external function.
