### Fixed

- Regular expressions: a back-reference to a capturing group that did not participate in the match matches the empty string, and a group inside a repeated group participates only if it matched in the current iteration, as F&O 3.0 5.6.1 defines it (`matches("x", "(a)|\1")` and `matches("babadad", "^((.)?a\2)+$")` are true; QT3 fn-matches-50). This applies to `fn:matches`, `fn:replace` (`$N` for such a group is the empty string), `fn:tokenize` and `fn:analyze-string`. With ICU, patterns with a back-reference are matched by Zorba's own regular expression engine, whose matcher was rewritten as a backtracking matcher with these semantics; other patterns still use ICU.
- Regular expressions: a back-reference to a group that contains other groups, such as `\1` in `^((a)(b))\1$`, no longer raises FORX0002.
- Regular expressions without ICU: `^` in `fn:tokenize` and `fn:analyze-string` matches only at the start of the input (or of a line with the `m` flag), not at the start of each search; with the `x` flag, whitespace is removed everywhere outside character classes (also before quantifiers and inside `\p{...}`); `"\"` in the replacement string of `fn:replace` escapes the next character, so `$10` with one group is group 1 followed by `0`.
