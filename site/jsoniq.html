JSONiq

JSONiq takes the XQuery machinery (sequences, FLWOR, functions, modules, updates) and points it at JSON. Objects and arrays become items, null becomes a value, and navigation gets a syntax that looks like JavaScript.

Two syntaxes

Zorba implements JSONiq 1.0 in two forms, and they share one data model and one function library:

  • The JSONiq syntax, used for files ending in .jq or with the --jsoniq flag. It adds $o.key lookups, $a[[i]] and $a[] for arrays, the literals true, false and null, and uses $$ for the context item because . is taken.
  • The JSONiq extension to XQuery, used in .xq files. JSON constructors work as in JSONiq, but navigation is done by calling objects and arrays like functions: $o("key"), $a(1), $a(). See JSON in XQuery syntax.

Everything on the XQuery page applies to both, apart from those syntax differences. Most examples here use the JSONiq syntax.

Objects and arrays

JSON is written as JSON. Any value position can hold an expression, including a FLWOR that fills an array.

Why it matters: output is built from typed values and serialized by Zorba, so quoting and escaping cannot go wrong.

Navigation

A dot looks up a key. The key can be a name, a quoted string (for keys with spaces or symbols) or a variable. [[n]] picks the n-th member of an array, counting from 1, and [] unboxes all members into a sequence.

Why it matters: lookups apply to every item of a sequence, so $order.items[].sku walks into every item at once, like a path in XPath.

Keys, members, size

The JSONiq function library works without a prefix: keys returns the keys of an object, members the members of an array, size the number of members.

Why it matters: with keys you can process objects whose keys you do not know in advance, such as dictionaries keyed by id.

The context item is $$

Inside a predicate or after the simple map operator !, the current item is $$ in JSONiq syntax.

Why it matters: code ported from XQuery needs . rewritten to $$ when it moves into a .jq file.

Null and absent keys

A key can be present with the value null, or absent. A lookup of an absent key returns the empty sequence, so comparisons on it return the empty sequence too. When an object value expression returns the empty sequence, the constructor stores null; that is why the second order shows null in the first comparison.

Why it matters: you decide whether "null" and "missing" mean the same thing for your data, and test for each separately when they do not.

Types

JSONiq names the JSON types directly: object, array, null, and the atomic types string, integer, boolean and so on without the xs: prefix. json-item matches objects and arrays.

Why it matters: heterogeneous JSON, where a field is sometimes a string and sometimes an array, is handled with one typeswitch.

Merging objects

{| ... |} merges a sequence of objects into one. Combined with a FLWOR it builds objects whose keys are computed.

Why it matters: computed keys turn a list into a dictionary in one expression.

Updates

JSONiq updates mirror the XML ones: insert json, delete json, replace value of json, rename json and append json. They follow the same rules: changes are collected and applied together, and copy/modify/return applies them to a copy.

Why it matters: JSON documents can be modified in place, in a collection or in a copy, with the same guarantees as XML updates.

JSON in XQuery syntax

In .xq files the dot is part of names ($o.name would be a variable called o.name), null would be a path step, and . is the context item. So objects and arrays are called like functions, jn:null() produces null, and the JSONiq functions are called through the jn prefix, bound by importing http://jsoniq.org/functions. (Unlike in .jq files, not all of them resolve without the prefix: members does not.)

JSONiq and XQuery 3.1
