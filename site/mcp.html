Querying a folder from an AI agent (MCP)

Point zorba-mcp at a folder of XML, JSON and CSV files and an AI agent can ask questions across all of them with JSONiq, without you converting or loading anything.

What it is

zorba-mcp is a Model Context Protocol server that speaks JSON-RPC over standard input and output. The agent's client starts it, and the agent gets tools to list the files in the folder and to run JSONiq or XQuery over them. The files stay where they are: every call reads them as they are on disk, nothing is indexed or cached.

The same engine and the same restrictions are available without an agent as zorba --directory (see below). The server implements MCP 2026-07-28 (server/discover) and also answers clients that start with the earlier initialize handshake (2025-11-25, 2025-06-18, 2025-03-26).

The folder is read through the directory module, http://zorba.io/modules/directory. A file is a record { "path", "format", "content" }: content is a document node for XML, the parsed value for JSON (an array if a file holds several top-level values, as in JSON Lines) and an array of row objects for CSV, with the first line as column names. A file that does not parse yields { "path", "format", "error" } instead, so one bad file does not stop a query over the whole folder. HTML files are listed with the format html but are not parsed yet.

Try it with Docker

No build is needed. The container image includes zorba-mcp; mount the folder you want to query at /data, read-only:

docker run -i --rm -v "$PWD:/data:ro" ghcr.io/zorba-processor/zorba:edge zorba-mcp --root /data

-i keeps standard input open, which is how the client talks to the server. The command waits silently for JSON-RPC messages, so you normally start it from an MCP client (next sections) rather than by hand. To check it by hand, send one request:

echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25"}}' \
  | docker run -i --rm -v "$PWD:/data:ro" ghcr.io/zorba-processor/zorba:edge zorba-mcp --root /data

The edge tag is the latest master build. The latest tag moves only on stable releases and does not include zorba-mcp until the first one that does; see docker/README.md for all tags. Any other arguments to the image still go to zorba, so docker run --rm ghcr.io/zorba-processor/zorba:edge -q '1 + 1' works as before.

Build from source

On Linux or macOS with the prerequisites installed, the full-release preset builds zorba-mcp along with zorba:

cmake --preset full-release
cmake --build --preset full-release
cmake --install build/full-release --prefix "$HOME/zorba"
"$HOME/zorba/bin/zorba-mcp" --root /path/to/folder

Install it rather than running it from the build directory: the installed tree is what puts the directory module and the file and CSV modules where the server finds them.

OptionEffect
--root <dir>The folder to query. Required.
--queries <dir>Each <name>.jq file in this folder becomes a tool, see the tools.
--timeout <seconds>Time limit of one tool call. Default 30; 0 means no limit.
--max-output <bytes>Output size limit of one tool call. Default 131072.

Register it with a client

Claude Code

Use an absolute path for the folder. Everything after -- is the command that starts the server:

claude mcp add --transport stdio zorba -- \
  docker run -i --rm -v /abs/path/to/folder:/data:ro \
  ghcr.io/zorba-processor/zorba:edge zorba-mcp --root /data

Without Docker, give the installed binary instead: claude mcp add --transport stdio zorba -- "$HOME/zorba/bin/zorba-mcp" --root /abs/path/to/folder. claude mcp list shows whether the server connected, and /mcp inside Claude Code lists its tools. By default the server is added for you in the current project; --scope project writes it to a .mcp.json you can commit, and --scope user makes it available in every project. Claude Code's MCP documentation has the details.

Any other MCP client

Clients that read an mcpServers block (Claude Desktop, Cursor and others; the file name and location differ) take the same command as JSON:

{
  "mcpServers": {
    "zorba": {
      "command": "docker",
      "args": ["run", "-i", "--rm",
               "-v", "/abs/path/to/folder:/data:ro",
               "ghcr.io/zorba-processor/zorba:edge",
               "zorba-mcp", "--root", "/data"]
    }
  }
}

The tools

ToolWhat it does
list_documentsLists the files under the folder, recursively and sorted by path, one JSON object per line: { "path", "format", "size", "modified" }. The format (xml, json, csv, html or null) says how the directory module would parse the file.
run_queryRuns a JSONiq or XQuery main module, given as the argument query, and returns the result as JSON, one item per line. On failure the result is an error object with the Zorba error code, the message and the line and column of the failing expression, which is what lets an agent correct its query.
Predefined queriesWith --queries <dir>, each <name>.jq file becomes a tool <name>. Its leading comment is the tool's description and its external variables (declare variable $id external;) are its string parameters. Use them for the questions you want answered the same way every time.

A predefined query is an ordinary query. With the folder from the next section, this file as queries/customer_name.jq gives the agent a tool customer_name with one parameter, id (mount the folder with -v /abs/path/to/queries:/queries:ro and add --queries /queries):

(: Returns the name of the customer with the given id. :)
import module namespace dir = "http://zorba.io/modules/directory";

declare variable $id external;

for $row in dir:open($dir:root, "customers.csv")("content")()
where $row("id") eq $id
return $row("name")

Example queries

A query sees the folder through $dir:root and these functions of the directory module: dir:list($dir:root), dir:open($dir:root, $path) for one file and dir:documents($dir:root, $formats) for all files of the given formats (default: all). The examples use a folder with this layout, which the project's image tests also use:

customers.csv            id,name,country  (acme: Acme Corp, MX; globex: Globex, US)
orders/2026/q1.xml       orders o1 (acme, 100) and o2 (globex, 250)
orders/2026/q2.xml       order o3 (acme, 75)
payments/payments.json   [ {"order": "o1", ...}, {"order": "o3", ...} ], both "paid"

Revenue per customer, from XML

import module namespace dir = "http://zorba.io/modules/directory";

for $o in dir:documents($dir:root, "xml")("content")//order
let $customer := string($o/@customer)
group by $customer
order by $customer
return {
  "customer" : $customer,
  "orders" : count($o),
  "total" : sum(for $t in $o/total return xs:integer($t))
}
{ "customer" : "acme", "orders" : 2, "total" : 175 }
{ "customer" : "globex", "orders" : 1, "total" : 250 }

Orders with no payment, joining XML with JSON

import module namespace dir = "http://zorba.io/modules/directory";

let $paid := dir:open($dir:root, "payments/payments.json")("content")()
               [$$("status") eq "paid"]("order")
for $o in dir:documents($dir:root, "xml")("content")//order
where not(string($o/@id) = $paid)
return {
  "order" : string($o/@id),
  "customer" : string($o/@customer),
  "total" : xs:integer($o/total)
}
{ "order" : "o2", "customer" : "globex", "total" : 250 }

Order totals per customer name, joining XML with CSV

import module namespace dir = "http://zorba.io/modules/directory";

let $orders := dir:documents($dir:root, "xml")("content")//order
for $c in dir:open($dir:root, "customers.csv")("content")()
return {
  "customer" : $c("name"),
  "country" : $c("country"),
  "total" : sum(for $t in $orders[@customer = $c("id")]/total
                return xs:integer($t))
}
{ "customer" : "Acme Corp", "country" : "MX", "total" : 175 }
{ "customer" : "Globex", "country" : "US", "total" : 250 }

Results should be JSON objects, arrays or atomic values; convert XML nodes with string() or data() before returning them.

Security model

The agent writes the queries, so the server treats every query as untrusted. Queries run under Zorba's secure policy with exactly two capabilities added back:

  • Read-only. File writes are denied, and so are environment variables.
  • Confined to the root. Reads are limited to files under --root. Absolute paths, .. segments and paths through symbolic links are rejected, symbolic links are not listed, and entries whose name starts with . are not listed.
  • No network. fn:doc on a URL, the HTTP client, external XML entities and importing modules or schemas over the network are all denied.
  • Native modules limited to the file module. Importing any other module implemented in C++ (for example the sleep or query-evaluation modules) raises zerr:ZXQP0067. The file module stays available because the directory module reads through it, and its reads are still confined to the root.

The server writes only protocol messages to standard output; its log goes to standard error. With Docker, mounting the folder with :ro adds a second, independent barrier. The project's tests exercise each denial above.

Limits and timeouts

  • A tool call stops after --timeout seconds (default 30) with the Zorba error zerr:ZXQP0068; --timeout 0 removes the limit.
  • Output longer than --max-output bytes (default 131072) is cut and ends with a line saying that the output was truncated.
  • A single JSON-RPC message larger than 4 MB is refused.
  • Every call re-reads and re-parses the files it touches, so a query over a large folder costs time proportional to the files it opens. Filter by path or format with dir:list or the $formats argument before opening documents.
  • HTML files are listed but not parsed yet. Zorba 5.0 is not thread-safe, so the server handles one request at a time.

From the command line: --directory

zorba --directory <dir> runs a query under the same policy as zorba-mcp: reads confined to <dir>, no writes, network or environment, only the file module among the native modules. $dir:root is bound to the folder, and the result is written as JSON, one item per line. It is the quickest way to write and test a query before giving it to an agent or saving it as a predefined query:

zorba --directory shop -f -q revenue.jq
docker run --rm -v "$PWD:/work" ghcr.io/zorba-processor/zorba:edge --directory shop -f -q revenue.jq

--directory cannot be combined with --allow or the other options that would widen the policy.
